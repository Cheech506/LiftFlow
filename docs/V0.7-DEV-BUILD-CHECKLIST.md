# LiftFlow v0.7 Development Build Checklist

Do not delete Expo Go until the installed LiftFlow app has restored and verified the current JSON backup.

## 1. Protect the existing data

- [ ] Open the v0.6 Expo Go copy of LiftFlow.
- [ ] Open Settings and export a full JSON backup.
- [ ] Save the backup somewhere outside Expo Go, such as the Files app and the Mac.
- [ ] Confirm the backup reports storage version 12.
- [ ] Keep the current v0.6 source and Git commit available for rollback.

## 2. Validate the v0.7 source

From the LiftFlow project on the Mac:

```bash
nvm use
npm ci
npm run check
npx expo-doctor
npx expo config --type public
```

- [ ] Automated tests pass, including the development-build configuration tests.
- [ ] Expo Doctor passes.
- [ ] The public config reports `com.cheech.liftflow` for both native platforms.
- [ ] The config reports LiftFlow version 0.7.0, iOS build 1, and Android version code 1.
- [ ] `npm ci` installs the lockfile-pinned `expo-dev-client` 6.0.21 packages without changing `package-lock.json`.

## 3. Generate and install the local iPhone build

```bash
npm run prebuild:clean -- --platform ios
open ios/LiftFlow.xcworkspace
```

- [ ] Xcode has the Apple Account under Settings → Accounts.
- [ ] The LiftFlow target uses Automatically Manage Signing.
- [ ] The intended Personal Team or paid Apple Developer team is selected.
- [ ] The connected iPhone trusts the Mac and has Developer Mode enabled.
- [ ] LiftFlow builds and installs from Xcode with its own icon.
- [ ] LiftFlow opens independently without opening Expo Go.

## 4. Restore the Expo Go data

- [ ] Open the installed LiftFlow app and go to Settings.
- [ ] Confirm Settings says **Installed development build** and **LiftFlow v0.7.0**.
- [ ] Tap **Restore your Expo Go backup**.
- [ ] Confirm the restore preview reports the expected exercise, template, and completed-workout counts.
- [ ] Complete the restore and wait for the success confirmation.
- [ ] Confirm the five workout templates and two folders are present.
- [ ] Confirm approximately 379 completed workouts are present.
- [ ] Open several imported Strong workouts and verify dates, exercises, sets, and import labels.
- [ ] Open several exercise pages and verify History, charts, and PR timelines.
- [ ] Confirm preferences, custom exercise notes, incomplete workouts, and Recently Deleted content are preserved.
- [ ] Force-close the installed LiftFlow app three times and confirm the restored SQLite data remains.
- [ ] Export a new v0.7 JSON backup from the installed app and retain it separately.

## 5. Test native-only behavior

- [ ] Enable rest-timer notifications and grant LiftFlow notification permission.
- [ ] Complete a set, lock the phone, and confirm the rest alert arrives.
- [ ] Export a JSON backup and CSV history file through the native share sheet.
- [ ] Open the native document picker and confirm backup restore can read a valid file.
- [ ] Start a workout, force-close LiftFlow, reopen it, and confirm the Resume bar restores it.
- [ ] Finish the workout and confirm History and Progress update.

## 6. Test daily development-client use

Start Metro on the development computer:

```bash
npm start
```

For the existing remote LiftFlow port:

```bash
npm run start:tunnel -- --port 8082
```

- [ ] The installed LiftFlow development client connects to Metro.
- [ ] A TypeScript-only change reloads without rebuilding in Xcode.
- [ ] Force-closing and reopening LiftFlow reconnects to the recent development server.
- [ ] WeekFlow continues running separately and is not stopped during LiftFlow testing.

## 7. Completion gate

- [ ] The installed app works without Expo Go.
- [ ] Existing LiftFlow data is verified and independently backed up.
- [ ] Free-signing expiration or paid-team signing behavior is understood.
- [ ] No credentials, certificates, provisioning profiles, `ios`, or `android` build output are staged in Git.
- [ ] The full automated and real-device checks pass before committing v0.7.

After this gate passes, LiftFlow is ready for the private Docker/PostgreSQL backend and offline synchronization batch.
